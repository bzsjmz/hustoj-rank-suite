# 历史单日新增总榜

命令：`/历史单日榜 [页码]`，每页 20 条；`/翻页 [页码]`继续查看。

每条记录对应一个用户在一个北京时间自然日的 AC 总量增量。同一个用户可在多个日期上榜；按新增量降序，相同新增量并列（1、1、3），同分按日期、学号升序显示。仅纳入已结束日期、新增量大于零且符合主年级学生学号规则的账号，沿用当前排除名单。现有 `/刷题榜` 保留今日文字查询功能。

## 统计口径与数据限制

使用起止两个零点各自之前（包括恰好零点）的最近完整快照，允许最多提前 30 分钟。数值是两个快照的 AC 总量差值，是自然日的近似统计，不是逐题首次 AC 事件统计。图片标注口径，文字备用逐条显示实际起止时间和日期。无时区的旧快照按北京时间解释，有时区的时间先转成北京时间。

首次部署的不足一天、缺少边界快照的日期不入榜；某账号在区间内任何完整快照缺失或出现 AC 总量下降，其当日记录不入榜。新账号缺少起点不将历史总量计入当天。未被快照观测到的重判、回退或回退后恢复无法识别；中间采集间隔不改变端点差值，但也无法精确分配实际提交日期。

每次成功发布后启动至多一个后台进程，回填 SQLite 中所有可计算的历史日期，不能还原采集前历史。采集发布只读取已完成的缓存，不等待历史扫描；首次发布可以为空，后续发布逐步纳入已完成记录。图片和文字在回填未完成时标注“后台统计更新中”，不是完整历史榜。

后台进程降低 CPU 调度优先级，在同一数据库的专用文件锁保护下逐日计算、逐日提交，每日间隔至少 50 毫秒；检测到内存或 I/O 压力后退出，下次成功发布继续。服务退出时停止子进程，已提交日期保留。进程继承采集服务的用户、环境及资源上限，没有新增长期服务或生产权限。之后使用每个日期的源快照 ID 列表作为签名，未变化的日期不重读历史用户行。`daily_record_days`、`daily_ac_records` 和 `daily_record_progress` 是可重算缓存，不修改原始历史快照；每个用户日期只有一条记录。当前排除规则与学号规则在输出时应用。导出端统一输出带 `+08:00` 的端点，包括旧缓存中的无时区字段。

## 接入与升级

本修改基于提交 `b057091011484ed6debcc5f04b0299125473d6a1`。

1. 先按 `docs/DATABASE_BACKUP.md` 备份数据库；保留原代码、私有 `.env` 和插件配置。停采集与渲染服务后更新代码，更新 AstrBot 中已安装插件的同名代码文件（保留插件私有配置）。
2. 在仓库目录执行 `git apply --check /实际路径/historical-daily.patch`；成功后执行 `git apply /实际路径/historical-daily.patch`。若检查失败，先处理版本差异，不使用强制覆盖。
3. 执行后端和插件测试：

   ```bash
   .venv/bin/python -B scripts/run_tests.py
   (cd plugins/astrbot_plugin_oj_rank && ../../.venv/bin/python -B -m unittest discover -s tests -v)
   ```

4. 启动 `oj-rank.service`、`oj-rank-render.service`，重新加载 AstrBot 插件。下次成功采集会先发布 `historical-daily.json`，然后启动后台回填；完成记录在后续成功采集中发布。首次回填时间取决于历史规模，不阻塞主榜发布。
5. 执行 `.venv/bin/python -B -m app.publication_audit --verify-snapshot`，确认完整发布；在获准会话检查 `/历史单日榜`、`/历史单日榜 2`、`/翻页`。历史不足时应显示暂无数据。图片按需生成，服务不可用时降级文字。

数据文件参与 `current-data` 整套原子发布，插件每次查询固定一代。AstrBot 只读共享文件，不需要新增数据库或认证目录挂载，也不增加自动群推送。

## 验证情况

包含每日结算、回填幂等、缓存复用、并列及重复用户、时区、缺失基准、新账号、账号缺失、AC 回退，以及数据解析、图片分页和缓存测试。实际 OJ 登录与真实机器人会话需在部署服务器验证。

新增回归覆盖：发布端不扫描原始历史、逐日提交及中断恢复、后台进程不重叠、启动失败不影响发布、混合时区端点、旧缓存端点规范化、旧图片页数与当前数据不一致，以及未完成统计的文字提示。真实 PNG 布局、真实 OJ 认证和生产历史规模下的资源表现仍需在获授权部署时验证。
